# X投稿用作業記録スキル

このプロジェクトの作業記録は、施主(ヨシボウさん)がXにコピー&ペーストで投稿できる
記事として書く。内部向けの開発日誌ではなく、読者が「浄土再現」に関心を持てる読み物にする。
成果物は毎日2つ:記事(.md)とタイトル入りサムネイル(.png)。どちらも `diary/` に置く。
`diary/` はObsidian Gitでヨシボウさんの Vault に自動同期されるため、コミット&プッシュが「Obsidianへの投稿」を意味する。

## 成果物と命名

- 記事: `diary/YYYY-MM-DD-X投稿用.md`(1日1ファイル。同日に再実行したら上書き更新)
- サムネイル: `diary/YYYY-MM-DD-thumbnail.png`(1600×900)
- コミット後、SendUserFileで両方をチャットにも添付する(施主はスマホで受け取って投稿することが多い)

## 記事の書き方

**まず `references/exemplar-2026-08-17.md` を読むこと。** 施主本人が仕上げた決定版であり、
文体・構成・温度のすべての規準。`diary/STYLE.md` は下敷きだが、X記事では以下が優先される。

型(お手本から抽出):

1. **冒頭挨拶** — 「こんにちは、ヨシボウです。」で始める
2. **プロジェクト紹介** — 「お経をプロンプトにして、極楽浄土を再現しようというプロジェクト」
   +『仏説阿弥陀経』のブラウザ3D化という一言説明。毎回入れる(初見読者のため)
3. **今日の作業は3つ。** — 「・」の箇条書きでその日の作業を列挙
4. **見出し付きセクション** — 「⸻」や「＿＿＿＿＿」の区切り線+短い見出し行
   (例:「Fableが作った木のアセットが酷すぎた」)で2〜3セクション
5. **締め** — 明日の予定をゆるく(「明日は蓮を作ってみようかな?」)+
   「じっくり、焦らず、コツコツ作っていきます!」系の前向きな一言

トーン(重要):

- **口語のツッコミと笑いを入れる**。「え?なにこれ?ファミコン以下のクオリティやん!」
  「ひどいものをあげてきたんですよw」— 「w」も感嘆符も使ってよい
- **FableというAIを登場人物として書いてよい**。施主がFableに指示し、Fableが失敗し、
  やり直させる——この掛け合いが読み物の核になる。失敗は率直に、しかし楽しく書く
  (「Fableを信用しすぎていたぼくが悪いのですがね。。」のような自虐も)
- ゲーム機の例え(ファミコン→PS3)のような、読者の肌感覚に届く比喩を使う
- 具体性優先:ツール名・研究者名・数字・出典(sketchfab等)を出す
- 一人称は「ぼく」。絵文字・マークダウン記法・URLは使わない
- 分量は800〜1,200字目安

書き終えたら `scripts/check_style.py` を走らせる。エラー(僕/マークダウン/絵文字)は必ず直す。
語尾や文長の指摘は参考程度でよい(口語のリズムを優先する)。

## サムネイルの作り方

実際の3D空間から撮る。合成イラストではなく「投稿を見て歩きに来た人が同じ景色に出会える」ことが価値。
メイン世界に見せ場がない日は、ギャラリーページ(gallery.html)のスクリーンショットでよい
(UIのボタンごと写して構わない。陳列室の空気も記録のうち)。

手順:

1. `npm ci && npm run build`(既にdistが最新ならスキップ)
2. `scripts/thumbnail.mjs` を使う。タイトル文字列と出力先を引数で渡す:
   ```bash
   node .claude/skills/x-worklog/scripts/thumbnail.mjs "記事タイトル" diary/YYYY-MM-DD-thumbnail.png
   ```
   スクリプト内のカメラ座標(CAMERA定数)は「その日いちばん見せたいもの」に向けて毎回調整する。
   新しい建立物(仏像・楼閣・蓮華など)ができた日は、必ずそれが主役になる構図にする
3. スクリーンショットを目で確認してから採用する。空が画面の半分を超えていたら失敗。
   地平線は上1/3、光の帯や道などの導線を対角に置くと締まる

デザインの約束事(スクリプトに実装済み、変える場合も精神は守る):

- 縦書きタイトルを右側に(掛け軸の見立て)。フォントはIPAGothic(この環境に明朝はない)、
  金色 #f5dc9e、字間広め、影で可読性確保
- 左下に小さく「『仏説阿弥陀経』3D再現プロジェクト ── 浄土再現」
- 文字の背後に暗いグラデーションを敷いて読みやすくする

## 仕上げ

1. 記事とサムネイルを `git add diary/ && git commit && git push -u origin <作業ブランチ>`
   (コミットメッセージは内容がわかる日本語で)
2. SendUserFileで記事とサムネイルをチャットに添付
3. 投稿タイミングの提案があれば一言添える(例:大きな節目の直後は引きが強い)

## 具体性を優先する(2026-08-16に施主が指示)

抽象的な物語より、具体的な事実で書く。ツール名(GitHub、Blender、tree-gen等)、
手法名、数字(ポリゴン数、葉の枚数、何分の1に軽くした等)は積極的に出してよい。
「検索したら参考になる方法が見つかって、その方法で作ることにした」のような
行動と決定の流れがそのまま読者への情報になる。
ただし専門用語には短い言い換えを添える(例:「Blenderという3D制作ソフト」)。

## してはいけないこと

- 技術用語を説明なしに羅列すること(数字や固有名詞は歓迎、羅列は退屈)
- 誇張や、実装していない機能の予告(「〜する予定です」は次フェーズの1件だけ許容)
- 個人情報(Vault名、ローカルパス、メールアドレス)を記事に入れること
- サムネイルの使い回し(その日の変化が画に出ることが記録の意味)
