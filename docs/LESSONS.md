## 1. 環境の限界(できないこと)

| できないこと | 詳細 | 対処 |
|---|---|---|
| GPU レンダリング | コンテナに GPU がない。Blender(bpy)は EGL がなく **render 不可**。Cycles の AO ベイクは最初のマテリアルにしか書けない | 見た目の確認は Vite ビルド + Playwright(swiftshader)で撮る。重いシーンはスクリーンショットに数分かかる(`timeout: 240000` を付ける) |
| 外部の 3D 生成 API | egress proxy が api.meshy.ai / api.tripo3d.ai / huggingface.co を遮断(npm・pypi のみ許可)。torch も入らない | image-to-3D は **施主が Tripo 等で生成**し、GLB を受け取って仕上げる |
| GitHub Actions の確認 | `actions_list` は 1 回で 7万〜29万文字返す | 呼ばない。プッシュ成功をもってデプロイ確認とする |
| 大きな画像の目視 | 1280x800 の PNG は約 1,365 トークン | 必ず `tools/inspect.sh <png> 640` で縮小してから見る。施主へ送る画像は縮小しない |
| コンテナの永続性 | 使い捨て。bpy / node_modules は消える | `pip install bpy pillow numpy && npm ci` で復元。http.server も落ちるので撮影前に `curl` で生存確認 |

## 2. アセット制作(Blender / bpy)での失敗

### 2-1. 手作りの造形は施主の期待に届かない
- 最初の木(プリミティブの寄せ集め)は「ファミコン以下」と言われ全削除(8/16)
- メタボールで自作した阿弥陀像は「ふざけてる?? ひどすぎるよ」で即却下(8/29)
- **教訓**: 有機的な造形(木・仏像・顔)はゼロから作らない。tree-gen のような既存ツール、Sketchfab 等の CC モデル、施主による image-to-3D を使う。手続き生成が向くのは建築・橋・台座など幾何学的なもの

### 2-2. スキャンモデルの後処理は「彫り」を壊す
- 平滑化を強くすると「溶けたみたい」になる。デシメートは細かい彫りを消す(ratio 0.5 で顔が消えかけた)
- テクスチャを剥がすと顔の特徴が消える(スキャンは色で顔を表現している)
- 顔の変形(目・鼻の押し出し)は「目がおかしい」「鼻が取って付けたみたい」になる → 全て元に戻した
- 法線マップの `Strength` が元データで 0.3 だった。いくら彫りを強めても最後で 7 割カットされていた → **元データの設定を最初に数値で調べる**
- **教訓**: スキャンから「美しい仏像」は作れない。磨き(amida_polish)までが限界。それ以上は image-to-3D へ

### 2-3. PBR マテリアルの落とし穴
- metallic ≥ 0.7 だとベースカラーのテクスチャがほぼ見えなくなる
- ベージュの空(PMREM 環境)を鏡面反射すると、金属も水も白飛びする → フレネルの自発光、または roughness を上げる
- 「錆びたような斑」は AO ベイクや法線の陰影。**施主が求めるのは均一な金一色**(`PED_GOLD=(0.85,0.62,0.20)`, metallic 0.72, roughness 0.52, 弱い emission)。台座と像は同じマテリアル定義にする
- `blur()` が負の値を切っていて法線が壊れた → 符号付きの `blur_signed` を使う
- 金一色にしても metallic 0.9 前後だと、空の青が映って**顔が青緑に濁る**(9/3)。metallic 0.75 / roughness 0.48 で解消。金箔の皺の法線は 0.3 混ぜると粒に見えてムラ扱いになる → 0.12 まで落とす

### 2-4. 形の破綻は数値で先に見つける
- 蓮華座の花弁が重なった(幅 > 間隔)、内側の輪が外側を突き抜けた、返花が浮いた(8/28)
- 八角楼の 2〜3 階が 0.95m / 0.4m 浮いていた、階段が八角形の角に当たっていた(8/23)
- 橋の接合、宝樹の原点ずれ(takara_tree は原点から約 (-9, -11) ずれている)
- **教訓**: 花弁数・幅は弧の間隔から計算する。段の接合は bpy で頂点のワールド座標を出して判定。スクショを何枚も撮って目で探さない

### 2-5. 施主の美的な要求の傾向(繰り返し言われたこと)
- 「もう少しテクスチャを細かく」「細部まで作り込んで」「誰が見ても感嘆するくらい」→ 常に **最初から最大の作り込み**で出す
- 「模様ではなく、材質の細かな描写を」→ 幾何学模様のテクスチャは「気持ち悪い」と言われる。金箔・槌目・磨きなど**材質感**のテクスチャにする
- 「花びらが尖りすぎ」→ 丸みのある先端(`round_tip`)
- 「クワガタみたい」→ 細くて反りの強い花弁は虫に見える。幅広・低カールに
- 「蓮が大きすぎる」(9/1)→ 車輪大 = 直径 1m 前後。手前の主役でも 1.2m まで
- アルカイックスマイル、険しい顔は NG(ただし顔の変形はそもそも不可 → 2-2)

### 2-6. MakeHuman(MPFB2)素体から仏像を組む試み(9/2、施主が断念)
- 人体素体 → 結跏趺坐 → 螺髪 → 衣、の手順で頭までは「とりあえずおけ」に到達したが、一往復 4 分 × 約 40 往復かかった
- 目を閉じる: メッシュ操作(穴・パッチ・溝)はすべて失敗。リグの瞼ボーンを回すのが唯一通った方法。目の縁は細い管で線を足す
- 螺髪: 表面サンプル + 詰め込み + 緩和で敷き詰める。まばら・はみ出し・耳にかかる、で三度組み直し。境界は黒い管で縁取る
- もみ上げの形だけで十回近く。「太い/細い/尖り/丸み」は 1〜2mm 単位の指示になる
- 体: 全身の凸包で衣を作ると「三角錐」になる。胴・腕・膝を別体積で作る。手を包んだ布の切り口に管を通すと「縄跳び」になる
- **教訓**: 木・楼閣・橋は一日で通るが、仏像は「人が違和感を覚える点の積み重ね」で、言葉と数字では届かない。
  次に仏像を作るなら、image-to-3D(Tripo 等)か既存モデルから始め、手続き生成では顔・手を作らない

### 2-7. 仏像の金色化は「色の置き換えだけ」(9/3)
- 法線を強め(0.3→0.85)、金箔の皺の法線を混ぜ、減面(0.7)した版は「チョコレートをかけたようにドロドロ」「螺髪が崩れてる」と却下
- 原型の法線(強さ 0.3)・分割・溶接なしのまま、ベースカラーの写真だけを金一色に替えた版で解消(18万tris・12MB)
- metallic 0.9 の鏡面寄りにすると、空の青が映って顔が青緑に濁る。台座と同じ metallic 0.75 / roughness 0.48 に留める
- **教訓**: 「表面の色を変えて」は文字どおり色だけ。法線・粗さ・減面のどれも触らない

## 3. 空間(Three.js / TSL)での失敗

| 失敗 | 原因 | 対処 |
|---|---|---|
| 水面が見えない | ベージュの空を鏡面反射して背景と同化 | フレネル^3 の自発光 `vec3(0.16,0.42,0.50)`、水中の砂を暗く |
| 水の円盤が岸を越えて浮いていた | 水面半径を固定値で書いていた | 水位線の半径を岸・島の斜面から計算(`bankWaterline` / `islandWaterline`) |
| 岸の斜面が裏返し | Cone の内側を見るのに FrontSide | `BackSide` |
| テクスチャの `clone()` が空 | 読み込み前の Texture を clone した | マテリアルごとに load する |
| 砂が荒い、波が小さい、池が小さい(8/25) | 初回の値が控えめすぎた | 粒 2px、池外周 30→38、波 0.16 + 0.045 の二重波 |
| N8AO(SSAO)で真っ白 → 効果なし → CI で `npm ci` 失敗 | `getTexture('output')` 等の名前が必要、ヘッドレスでは効かず、peer dep が three@^0.182 で 0.185 と衝突 | **外部ポストエフェクト系は入れない**。入れるなら `--legacy-peer-deps` を使わず、CI と同じ `npm ci` で通ることを確認してからプッシュ |
| 22m の橋が池に届かない | 池を広げたのに橋を作り直していなかった | 寸法は `layout.ts` の定数から導く。池を変えたら橋・水位線・歩行判定も追従させる |
| ギャラリーのスクショで狙った角度にならない | OrbitControls が lookAt を戻す。モデル底面が y=0(中心ではない) | `window.__controls.update = () => {}` してから camera を置く |
| 撮影スクリプトが途中で死ぬ | `pkill -f "http.server 8932"` が自分のシェルまで殺す(9/1)。heredoc の前に置くとファイルが書かれない | pkill しない。`curl` で生存確認して無ければ起動 |
| スクショのタイムアウト | 1,100 インスタンスのシーンは swiftshader で 30 秒を超える | viewport 960x600、`screenshot({ timeout: 240000 })` |

## 4. 仏像づくりの経緯(同じ轍を踏まないための年表)

1. Sketchfab のスキャン(CC-BY-SA)を金に塗装 → 「木彫のまま」感、斑が残る
2. 「磨き」処理(CLAHE・法線強調)で amida_polish → ここが後処理の上限。**アセットとして保存済み**
3. メタボールで自作 → 即却下
4. 蓮華座を合体させた amida_full → 色統一の要求で全マップ剥がし、金一色。顔の輪郭は出せず「直ってない」
5. GitHub で他手法を調査 → 施主「イラストとキャラクターシートから作るやつはないの?」
6. キャラクターシート(正面・側面・背面の切り出し 1024²、白背景)を用意 → 環境から API 不可 → **Tripo で施主が生成中**
7. 届いたら: 数値で寸法確認 → 金一色マテリアルに統一(2-3 の値)→ 最適化 → ギャラリー登録 → ATTRIBUTION.md → 承認後に中島の蓮華座(scale 3, ISLAND_TOP)へ

**次に仏像を触るときのルール**: 顔の形状は絶対にいじらない。マテリアルは台座と同一。「はっきりさせて」は法線の Strength とライティングで応える。無理なら無理と言う。

## 6. 施主とのやり取りで学んだこと

- 施主は数値より**見た目の一言**で判断する(「浮いてない??」「クワガタみたい」「厚化粧」)。その一言は正確なので、疑わず原因を数値で探す
- 「正直に答えてね?」と聞かれたら、出典や限界をそのまま言う(Sketchfab 由来であることは隠さない)
- 大きな作業の途中でも「今日はここまで」で日記(x-worklog)を書く。失敗も日記に率直に書く。施主はそれを読み物として楽しんでいる
- 報告は要点のみ。作業ログの実況はしない
